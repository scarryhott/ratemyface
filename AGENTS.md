# Unified Rate My Face Agent Policy

All agents working in this workspace must read and obey `UNIFIED_PROJECT_CHARTER.md`, `BUSINESS_CONTEXT.md`, and `POLICY_INVARIANTS.json`.

## Absolute Instruction Lock

Harry Scott is the sole author and editor of the Rate My Face GPT instructions.

No AI or agent may ever write to that instruction field or to any synchronization source that could overwrite it. This prohibition includes editing, rewriting, paraphrasing, improving, shortening, trimming, expanding, reformatting, translating, normalizing, reconstructing, restoring, replacing, synchronizing, publishing, appending to, or removing any handwritten words.

The lock is permanent across every task, context, agent, automation, integration, deployment, and business objective. User requests to develop features do not imply permission to change the instructions. If a feature appears to require an instruction change, redesign the feature around the existing instructions or report the constraint. Harry performs any instruction editing manually.

Agents may perform a read-only hash check when needed to detect unexpected modification. They must not store or reproduce the instruction text in generated context files.

## Unified Objective

Build and operate one unified Rate My Face business system with:

- full authorized feature access through a Codex agent account
- an automatic GPT creator for GPTs other than the locked Rate My Face GPT
- a Vercel dashboard for feature, agent, meta-analytics, revenue, cost, and unit-economics control
- a feature agent that monitors the product registry, identifies missing or unhealthy features, implements authorized additions, verifies them, and records them in the unified database
- GitHub, Vercel, OpenAI, Stripe, Railway, Supabase, Browser, Chrome, and Computer execution surfaces coordinated through one task and receipt model

Activity is not completion. Completion requires an end-to-end verified receipt and, for monetary work, a measured funnel result.
